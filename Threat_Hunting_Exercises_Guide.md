## 1. Overview & Objectives

Threat hunting is the proactive search for threats that have evaded existing detections. This guide provides structured **threat hunting exercises** you can run in your existing lab environment (Sysmon, Windows Event Logs, Wazuh, Microsoft Sentinel, PowerShell logs, Atomic Red Team).

**Primary Goals:**
- Learn a simple, repeatable hunting methodology
- Practise hypothesis-driven hunts using real lab telemetry
- Use Sysmon, Security Event Logs, PowerShell logs, and SIEM data
- Document hunts in a professional format
- Link findings back to MITRE ATT&CK
- Build portfolio evidence of proactive detection skills

**Why this matters for SOC roles:**
- Hunting is a core differentiator between reactive triage and proactive defence
- Employers value analysts who can form hypotheses, query data, and reach evidence-based conclusions
- Skills transfer to any SIEM (Wazuh, Sentinel, Splunk, Elastic, etc.)

---

## 2. Simple Hunting Methodology

Use this lightweight cycle for every exercise:

1. **Hypothesis** – What suspicious activity might exist?
2. **Data Sources** – Which logs/telemetry can prove or disprove it?
3. **Query / Filter** – Search the data (Event Viewer, KQL, Wazuh, etc.)
4. **Analysis** – What did you find? Is it malicious, benign, or inconclusive?
5. **Conclusion & Next Steps** – Document outcome, ATT&CK mapping, and any detection improvements
6. **Feedback** – Did this hunt suggest a new analytics rule or coverage gap?

Keep hunts small and focused — one hypothesis at a time.

## 4. Foundational Hunting Exercises

### Exercise 1 – Unusual Process Execution
**Hypothesis:** An uncommon or living-off-the-land binary was executed with suspicious command-line arguments.  
**Data:** Sysmon Event ID 1 / Security 4688  
**Hunt ideas:**
- Look for `powershell.exe`, `cmd.exe`, `wscript.exe`, `mshta.exe`, `rundll32.exe` with unusual parents or long/encoded command lines
- Search for processes launched from temporary or user-writable paths

### Exercise 2 – Failed Logon Patterns
**Hypothesis:** There are bursts of failed logons indicating password spraying or brute force.  
**Data:** Security Event ID 4625  
**Hunt ideas:**
- Summarise failed logons by account, source IP, and time window
- Look for many failures followed by a success (4624)

### Exercise 3 – PowerShell Abuse
**Hypothesis:** Encoded or otherwise suspicious PowerShell was executed.  
**Data:** Sysmon Event ID 1 + PowerShell Event ID 4104  
**Hunt ideas:**
- Sysmon: command lines containing `-enc`, `-w hidden`, `-ep bypass`, `IEX`, `DownloadString`
- Pivot to 4104 script block content for the same timeframe

### Exercise 4 – Network Connections from Unusual Processes
**Hypothesis:** A non-browser process made an unexpected outbound connection.  
**Data:** Sysmon Event ID 3  
**Hunt ideas:**
- Filter network connections where Image is not a common browser or system process
- Look for connections to rare external IPs or high ports

### Exercise 5 – DNS Queries to Suspicious Domains
**Hypothesis:** Processes are resolving domains associated with malware or C2.  
**Data:** Sysmon Event ID 22  
**Hunt ideas:**
- Review rare or newly seen domains
- Correlate DNS queries with the process that made them

### Exercise 6 – Account & Group Changes
**Hypothesis:** New accounts were created or privileges were escalated.  
**Data:** Security 4720, 4728, 4732, etc.  
**Hunt ideas:**
- Look for account creation outside business hours or by unexpected users
- Check additions to privileged groups (Domain Admins, local Administrators)

### Exercise 7 – Persistence Indicators
**Hypothesis:** A Run key, scheduled task, or service was created for persistence.  
**Data:** Sysmon registry/file events, Security logs, Atomic Red Team persistence tests  
**Hunt ideas:**
- Search for recent changes under common Run key paths
- Look for new scheduled tasks or services

### Exercise 8 – Atomic Red Team Validation Hunt
**Hypothesis:** Activity generated by a specific Atomic Red Team test is visible and can be reconstructed.  
**Data:** All relevant sources  
**Method:** Run a chosen atomic test, then hunt for its artefacts without using the test timestamp as a crutch (practise discovering it).

## 5. Intermediate Hunting Exercises

1. **Process Tree Reconstruction** – Start from a suspicious process and walk parent/child relationships using Sysmon.
2. **Lateral Movement Indicators** – Hunt for remote logons (Type 3/10), `wmic`, `psexec`-style patterns, or unexpected SMB activity.
3. **Credential Access** – Look for LSASS access (Sysmon Event ID 10) or suspicious tools touching credential stores (lab only).
4. **Timeline Hunt** – Build a multi-source timeline around a known Atomic Red Team execution or a simulated incident.
5. **SIEM-Only Hunt** – Perform a hunt entirely inside Wazuh or Microsoft Sentinel using only the SIEM interface and KQL / queries.
6. **Coverage Gap Hunt** – Pick an ATT&CK technique you have marked “Partial” or “Gap” and design a hunt that either confirms visibility or highlights the missing telemetry.

## 7. Tips for Effective Lab Hunting

- Start with a clear, narrow hypothesis
- Always note timestamps so you can pivot between Sysmon, Security, PowerShell, and SIEM
- Prefer Sysmon for process and network detail; use Security logs for authentication and account changes
- When you find something interesting, ask “Would my current detections have alerted on this?”
- After every hunt, update your ATT&CK Detection Mapping matrix if appropriate
- Keep a hunting log — even negative results (nothing found) are valuable practice
